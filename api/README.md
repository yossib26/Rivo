# הדמיית שירותי חברות הביטוח

בעמוד ההצעות כל חברה נקראת בקריאת API משלה. אין קריאת רשת אמיתית: כל הכתובות בדומיין `.example`,
והמפתחות בכותרות הם ערכי דמה.

## קבצים

| קובץ | תפקיד |
| --- | --- |
| `insurer-api.js` | הלקוח המשותף: בקשה אחידה, הדמיית רשת ו"שרת", תמחור לפי פרופיל הסיכון, פענוח התגובה להצעה |
| `insurers/<חברה>.js` | הגדרת החברה: כתובת השירות, כותרות, מבנה ה-JSON של הבקשה והתגובה, כללי חיתום, מבנה שגיאת סירוב |
| `samples/<חברה>.json` | דוגמה לבקשה, לתגובת הצלחה ולתגובת סירוב של החברה (נוצרו מהקוד) |

החברות: הפניקס, הראל, מגדל, כלל ביטוח, מנורה מבטחים, ביטוח ישיר, שירביט, הכשרה, AIG, איילון.

## זרימת קריאה

1. בקשה אחידה (`standardRequest`) נבנית מפרטי הלקוח, הרכב, הנהגים והפוליסה הנוכחית.
2. הבקשה מתורגמת למבנה ה-JSON של החברה (שמות שדות, מקינון, יחידות ואנומים שונים בכל חברה).
3. "שרת" החברה מפענח את הבקשה, מפעיל כללי חיתום ומחזיר `200` עם הצעה, או `422` עם קוד סירוב, או `400` על בקשה לא תקינה.
4. התגובה עוברת כ-JSON לאחר השהיה שמדמה זמן רשת (כ-250 עד 700 מילישניות).
5. התגובה מפוענחת לתנאי הצעה אחידים. הקריאות לכל החברות יוצאות במקביל, אבל העמוד מציג את התשובות אחת אחרי השנייה, לפי סדר ההגעה, בהפרש של שנייה אחת (`REVEAL_GAP_MS` ב-`compare.html`). בסיום הרשימה מסודרת לפי מחיר. בעמוד ההצעות אפשר לפתוח מתחת לכל הצעה את ה-JSON המלא של הבקשה והתגובה.

## הוספת חברה

צרו קובץ ב-`insurers/`, קראו ל-`InsurerApi.register({...})` והוסיפו תג `<script>` ב-`compare.html`
וגם את שם החברה ב-`COMPANIES` שב-`loader.js`. הגדרה כוללת:

- `endpoint`, `headers`, `latency: [מינימום, מקסימום]`, `priceBias`
- `request` / `response`: `style` (`camel`, `snake`, `pascal`, `upper`), `layout` (`nested` / `flat`), `root`, `rename`, `values` (המרות ערכים), ואופציונלית `extra`, `wrap`, `unwrap`
- `rules`: כללי סירוב `{ code, message, when(std) }`
- `decline`: `shape` ו-`read` למבנה שגיאת הסירוב של החברה
